# Windows build and verification

## Supported baseline
- Unreal Engine 5.8.x (use the newest installed 5.8 hotfix).
- Visual Studio 2022 with Desktop development with C++ and Game development with C++ workloads, plus a Windows SDK supported by the selected engine version.
- Windows 10/11 64-bit.

The project uses C++ and the built-in PCG plugin. No third-party runtime plugin is required by the current source.

## First open
1. Install the matching Unreal Engine 5.8.x version through Epic Games Launcher.
2. Install the Visual Studio C++ workloads and Windows SDK.
3. Clone the repository locally.
4. Double-click `OPEN_WORLD_Next_Gen.uproject`.
5. Allow Unreal Editor to generate project files and compile the project when prompted.
6. Open the Output Log and resolve any compiler or asset errors before testing.

## Build from Visual Studio
1. Right-click the `.uproject` and generate project files if they were not generated automatically.
2. Open the generated solution.
3. Select `Development Editor` and `Win64`.
4. Build the `OpenWorldNextGenEditor` target.
5. Launch the project from Unreal Editor.

For a packaged build, use Unreal Automation Tool/Project Launcher with the Development configuration after the editor build succeeds. Record the exact engine hotfix and build output.

## World Partition authoring (editor task)
World Partition is a property of an editor-authored world/level; adding an INI flag alone does not convert the current runtime-generated greybox into a streamed open-world map.
1. In Unreal Editor create a new Open World level using the engine's Open World level template.
2. Save it under `Content/Maps/L_Praha_Prototype`.
3. Keep the initial test region small (approximately 1–2 km across); do not author all 400 km² at once.
4. Confirm World Partition is enabled in World Settings and inspect the generated streaming grid.
5. Add a World Partition Data Layer only when there is a concrete gameplay/editor need.
6. Place a small test district and verify cells load/unload while moving through the world.
7. Only after this editor-authored level is validated should the runtime greybox actor be migrated or replaced.

The .umap asset cannot be safely generated by editing text files; it must be created and saved by Unreal Editor.

## Performance test protocol
Use the same packaged Development build and repeatable route for each run. Record:
- CPU/GPU and driver versions
- Engine hotfix and graphics settings
- Resolution and upscaling settings
- Average FPS, 1% low and frame time
- RAM and VRAM usage
- NPC/traffic counts and streaming conditions

The target is 1080p/120 FPS, but no performance claim is valid until it is measured on the target PC (Ryzen 5 5600, RTX 5050 8 GB, 16 GB RAM). If the target is missed, profile first and reduce the actual bottleneck rather than guessing.

## Current verification status
The repository's static CI checks project metadata and expected source layout. It does not compile Unreal C++ or launch the editor. Those checks require the Windows/Unreal workstation.
